RTI Service Pipeline

How a sensor reading travels from the LoRa nodes to the map on screen, now that every backend job runs under one manager daemon. Three machines each own one stage. This page follows the data, file by file.

Backend server · backend/ · manager daemon + 4 services Postgres server · reached over Tailscale Your computer · app/

File-by-file reference

Backend server

Collect & supervise

backend/

  • manage_services.py Command line and terminal UI: status, start, stop, run-now, shutdown. Starts the daemon in the background if it isn't running, and talks to it with one JSON line over manage_services.sock.
  • manage_services.py daemon Runs each service in its own child process, 2 s apart. Stops with Ctrl+C, then SIGTERM after 15 s, then SIGKILL. Restarts crashes after 5 s, doubling up to 5 min. Won't start a copy already running outside it.
  • service_runtime.py The context each service gets: stopping(), wait(), idle() for run-now, and report() for the status shown in the UI.
  • master/main_senor_data.py Each node sends in turn and the others are polled for the packet. Writes one measurement row per link and one rounds row per round into sensor_data.db. Reads LoRa settings from node 1 instead of rewriting them.
  • postgres_schedule/sync_scheduled_postgres.py Opens sensor_data.db read-only and copies rows newer than Postgres's highest IDs. The manager runs it every 900 s; run alone it defaults to 2 h.
  • reduce_sqlite/scheduled_reduce_database.py At start-up and at 06:00 and 18:00, rebuilds reduced_data.db with rounds whose ID is divisible by 5, then runs VACUUM.
  • water_pumping/schedule_pump.py Runs 100 pump cycles at 09:50 and 15:30. Runs under the same manager, but touches no database.
Postgres server

Central copy

Tailscale

  • PostgreSQL Holds the full-resolution measurement and rounds tables. The sync creates them if they're missing.
  • postgres_schedule/.env Named profiles: MAIN_SQLITE_PATH with MAIN_TAILSCALE_DSN by default, or a local connection and a reduced source.
  • db_local/local_db_build.sh Builds a local sensor_data Postgres database from a dump, for testing.
Your computer

Compute & visualize

app/

  • database.py Pulls the backend's reduced_data.db by SFTP into reduced_data_<timestamp>.db when the newest local copy is older than 8 h. Also opens Postgres through an SSH tunnel or directly over Tailscale.
  • precompute_sequences.py Runs the RTI solver for each reference day and saves sequence_cache/<date>.joblib, removing files for days that no longer exist.
  • rti_temporal_core.py The spatial + temporal regularized solver and the cache helpers. Pure computation, no UI.
  • rti_temporal_visualization.py Draws the Matplotlib figure from the solver's output.
  • main.py Tk viewer. If the newest cache file isn't from today, it runs the precompute behind a progress window first, then loads cached sequences as you move the sliders.
Since the RTI Pipeline page: the sync now copies the full-resolution sensor_data.db every 15 minutes, where before it copied backup.db every 2 hours. The reduced file is now reduced_data.db, and the app's SFTP pull lives in database.py. All four backend jobs run under the manager daemon instead of separate nohup processes.
